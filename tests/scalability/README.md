# Scalability framework (kind + kwok)

Exploratory scalability testing for NetworkPolicy enforcers. Real enforcement
runs on a few kind workers (the *system under test*); [kwok](https://kwok.sigs.k8s.io)
supplies tens of thousands of fake Nodes and Pods so the agents ingest and
materialize control-plane state at scale without the cost of a large cluster.

The framework is DUT-agnostic. This repository ships three DUTs, the
kube-network-policies variants; other enforcers plug in through `dut/`.

```
tests/scalability/
├── cluster.sh            kind cluster + passive kindnet + kwok
├── run.sh                one experiment: install → fill → probes → churn → connrate → collect
├── collect.sh            Prometheus range queries + kernel state → _artifacts/<run>/
├── report.sh             Markdown + JSON summary of one or more runs → reports/
├── verify.sh             artifact completeness and enforcement assertions (CI)
├── lib.sh                shared helpers (render, logging, node discovery, kubectl context)
├── Makefile              cluster-up / run / matrix / smoke / report / lint
├── templates/            kind config, KNP DaemonSet, kube-ip-tracker, params.json
├── monitoring/           Prometheus deployment, scrape-base.yaml, queries.txt
├── scenarios/            NetworkPolicy templates: default-deny, gateway, mesh
├── probes/               real gateway/client Pods and fortio drivers
├── loadgen/              Go: fake nodes, rate-limited Pod creation, churn
├── reports/              committed reports generated by report.sh
└── dut/
    ├── knp/                  standard flavor, --disable-nri=true
    ├── knp-nri/              standard flavor, NRI enabled
    ├── knp-nri-iptracker/    iptracker flavor + kube-ip-tracker, NRI enabled
    ├── knp-lib.sh            shared install/uninstall/kernel-state for the three
    └── _template/            copy to add cilium, calico, ovn-kubernetes, antrea…
```

All manifests are YAML templates rendered with `envsubst` for an explicit list
of variables (`render` in `lib.sh`), so `${1}`-style placeholders in
Prometheus relabel rules and `$(MY_NODE_NAME)` pass through untouched.

## Requirements

`kind`, `kubectl`, `docker`, `go`, `curl`, `jq`, `envsubst` (gettext),
`shellcheck` for `make lint`. The kwok manifests are fetched from the pinned
release (`KWOK_VERSION`).

## Quick start

```sh
cd tests/scalability
make cluster-up                                    # kind (1 cp + 2 workers), kwok v0.8.0, Prometheus
make run DUT=knp-nri PODS=10000 IDENTITIES=700 SCENARIO=mesh
make matrix PODS=20000                             # 3 DUTs × {gateway,mesh} × {7,700,3500}
make report RUNS="_artifacts/<run-a> _artifacts/<run-b>"   # → reports/compare-*.md + one JSON per run
make cluster-down
```

`run.sh --help` lists every option. Artifacts land in `_artifacts/<run-id>/`:

| File | Content |
|---|---|
| `params.json` | every parameter, tool versions, real worker names |
| `phases.json` | `t0`/`t1` per phase so any metric can be sliced by phase |
| `results.json` | enforcement/revocation latency (ms), allowed/denied probe outcomes |
| `fill.log`, `churn.log` | achieved Pods/s from `loadgen` |
| `latency-fresh-connections.json` | fortio: 200 sequential no-keep-alive connections |
| `connrate-allowed.json`, `connrate-denied.json` | fortio: concurrent allowed + denied load |
| `prom/*.json` | one range-query result per line of `monitoring/queries.txt` |
| `kernel-state-steady.jsonl`, `kernel-state.jsonl` | per real worker, from `dut.sh kernel-state`, at steady state and at the end |
| `dut-pods.txt`, `agent.log` | effective image/args and agent logs |

## What is measured

The confounds the 720-node benchmark could not control are parameters here:

- **Achieved Pods/s** is fixed by `--rate` (Pods are created directly, not via ReplicaSets).
- **Identity cardinality** (`--identities`) is independent of Pod count.
- **Fresh vs reused identities** during churn (`--fresh-identities`) separates
  identity churn from Pod churn.
- **Enforcement latency**: time from policy apply until the allowed probe passes
  (`enforce_ms_idle`, `enforce_ms_loaded`) and from policy delete until the
  denied probe blocks (`revoke_ms`), measured on real Pods across two real nodes.
- **Negative enforcement** is checked on every run (`denied_ok_*`), not once.
- **Agent CPU/memory** (cAdvisor), **verdict rate, processing latency, queue
  depth and drops** (agent `/metrics` on `:9080`), **API-server watch fan-out
  and object counts**, **kernel state cardinality** (nftables sets, conntrack
  labels), and **connection-rate capacity** with a denied-traffic mix.

kwok Pods have addresses but no network namespace, so only the probe Pods
carry traffic. Everything agent-side (informer ingestion, selector evaluation,
set programming, memory) scales with the fake objects; the datapath numbers
come from the two real workers.

## Reports

`report.sh <run-dir>...` reduces each run to one flat JSON summary and writes a
Markdown report with comparison tables (enforcement latencies, connection path,
agent CPU/memory/queue, control plane, kernel state). Run ids embed the
parameters (`<dut>-<scenario>-i<identities>-p<pods>-<timestamp>`), so report
file names are self-describing. Committed reports live in `reports/`; the raw
artifacts they were built from stay in `_artifacts/` on the machine that ran
them. Prometheus series are reduced to max/mean over the whole run window;
slice by phase with `phases.json` against the raw `prom/*.json` if you need
finer detail.

The first committed report,
`reports/compare-knp-knp-nri-knp-nri-iptracker-20260918T183142Z.md`, compares
the three flavors at 20 fake nodes / 1,000 Pods / 200 identities under the
`mesh` scenario; it is a demonstration of the framework, not a performance
claim (one run per configuration). Reproduce it with:

```sh
for d in knp knp-nri knp-nri-iptracker; do
  ./run.sh --dut $d --nodes 20 --pods 1000 --identities 200 --namespaces 5 \
    --rate 100 --scenario mesh --churn-rate 10 --churn-duration 30s --steady 30s
done
./report.sh _artifacts/knp-mesh-* _artifacts/knp-nri-mesh-* _artifacts/knp-nri-iptracker-mesh-*
```

## CI

`.github/workflows/scalability-smoke.yml` runs `make lint`, renders every
template, then for each KNP DUT builds the image, creates the cluster and runs
`make smoke`: a 5-node/100-Pod experiment followed by `verify.sh`, which asserts
that every phase ran, all Pods reached Running, the denied probe was blocked and
the allowed probe admitted in every state, latencies were measured (no
timeouts), fortio produced results, the agent metrics have samples with both
accept and drop verdicts, no NFQUEUE kernel drops occurred, and kernel state was
captured on every worker. It checks that the framework works, not that
performance held; it runs on changes to `tests/scalability/`, on demand, and
weekly.

## Adding a DUT

```sh
cp -r dut/_template dut/cilium
$EDITOR dut/cilium/dut.sh          # install | uninstall | kernel-state <node>
# optional: dut/cilium/scrape.yaml  (scrape_configs list items)
#           dut/cilium/queries.txt  (name|PromQL, appended to monitoring/queries.txt)
make run DUT=cilium
```

Contract: `install` returns when the enforcer is ready on every real worker and
must keep its Pods off kwok nodes (`nodeAffinity: type NotIn [kwok]`); the
enforcer implements Kubernetes NetworkPolicy so `scenarios/` apply unchanged.
A DUT that is itself the CNI sets `KIND_DISABLE_DEFAULT_CNI=true` before
`cluster.sh up` and installs networking in `install`.

Check whether the DUT ingests kwok Pods the way it ingests real ones. Cilium,
for example, derives identities from Pod labels in the operator but creates
endpoints only for Pods on nodes running an agent; verify with a map dump
before drawing conclusions from its numbers.

## Coexistence with kindnet

kind's default CNI, kindnetd, bundles kube-network-policies in recent
versions. `cluster.sh` swaps in a kindnetd image that predates that
(`KINDNET_PASSIVE_IMAGE`) so the DUT is the only enforcer, the same approach
as `tests/setup_suite.bash`, and deletes the `kindnet-network-policies`
nftables table the original kindnetd programmed before the swap (its queue
rules and unconditional `ct label set` would otherwise sit at the same hook
priority as the DUT's chains). The three KNP DUTs use nfqueue ids 98 and 198
and the `kube-network-policies` table; `uninstall` removes the table on every
real node so the next DUT starts clean.

## Notes

- Every `kubectl` in the framework carries `--context kind-${CLUSTER_NAME}`
  (wrapper in `lib.sh`) and `run.sh` passes the same `--context` to `loadgen`,
  so a run is unaffected by the user's current context changing. Override with
  `KUBE_CONTEXT`.
- Fake Pod IPs come from `KWOK_POD_CIDR` (default `10.64.0.0/12`), disjoint
  from kind's Pod and Service ranges.
- `results.json` values of `-1` mean a probe timed out (120 s).
- Prometheus keeps 2 days of samples in an `emptyDir`; `collect.sh` runs at
  the end of each run, so nothing is lost if the cluster is deleted afterwards.
- `make lint` runs shellcheck and `go vet`.
- Host prerequisite: `fs.inotify.max_user_instances` of at least 1024 (kind
  nodes fail to boot systemd below that); `cluster.sh` warns if it is low.

Reference smoke run (`knp-nri`, 20 fake nodes, 500 Pods, 50 identities, mesh,
two 4-vCPU-class kind workers on one host): enforcement latency ~300 ms,
revocation ~2.3 s (strict-mode conntrack scan), fresh-connection p50/p99
0.7/1.0 ms, 8.3k connections/s at c=64 with p99 13.9 ms, agent peak 1.5 cores
on the gateway node, queue depth peak 43 of 1,024, zero drops.
